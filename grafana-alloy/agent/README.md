# Alloy Agent — шаблон для мониторимых хостов

Разворачивается на каждом хосте, который нужно мониторить. Собирает
системные метрики (CPU/RAM/диск/сеть) и логи Docker-контейнеров, отправляет
их на центральный Alloy (см. `../server`).

## Быстрый старт

```bash
cp .env.example .env
# укажите адрес центрального Alloy
docker compose up -d
```

## Что собирается

- **Метрики хоста** — `prometheus.exporter.unix` (аналог node_exporter),
  для этого хостовые `/proc`, `/sys` и `/` монтируются read-only.
- **Логи контейнеров** — `loki.source.docker` через Docker socket
  (read-only монтирование `docker.sock`).

Каждому агенту автоматически проставляется label `host` (имя хоста
контейнера или `HOSTNAME_OVERRIDE` из `.env`) — так в Grafana можно
фильтровать метрики/логи по конкретной машине.

## Безопасность

- `docker.sock` монтируется **read-only**, но сам факт доступа к сокету
  даёт возможность читать метаданные всех контейнеров хоста — учитывайте
  это в модели угроз.
- `/proc`, `/sys`, `/` монтируются read-only и используются только
  экспортером метрик.
- Трафик до центрального Alloy используйте через приватную
  сеть/VPN/reverse-proxy с TLS — по умолчанию шаблон не шифрует канал
  между агентом и сервером.

## Best practices, заложенные в шаблон

- Healthcheck через `/-/ready`.
- Лимиты CPU/RAM (агент лёгкий: по умолчанию 0.5 CPU / 256m RAM).
- Ограничение размера логов контейнера.
- `no-new-privileges`.
- Именованный том для WAL/состояния Alloy (`alloy_agent_data`).
