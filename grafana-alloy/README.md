# Grafana + Grafana Alloy

Шаблоны для мониторинга: центральный стек `server/` (Grafana + Alloy как
точка приёма телеметрии) и `agent/` — Alloy-агент для установки на
удалённые/мониторимые хосты.

## Структура

```
grafana-alloy/
├── server/   # Grafana + центральный Alloy (приём + визуализация)
└── agent/    # Alloy-агент для развёртывания на каждом хосте
```

## Важное архитектурное допущение

Alloy — это коллектор/пересыльщик, а не база данных временных рядов или
хранилище логов. Grafana тоже не хранит данные сама — ей нужен источник
данных (datasource). Поэтому шаблон рассчитан на то, что у вас уже есть
(или вы поднимаете отдельно) backend для метрик и логов:

- self-hosted **Grafana Mimir** (метрики, Prometheus remote_write совместим)
  и **Grafana Loki** (логи), либо
- **Grafana Cloud** (Prometheus/Loki endpoints с basic auth по API key).

Центральный Alloy (`server/`) принимает данные от агентов и пересылает их
в этот backend; Grafana провижинится с датасорсами, указывающими на тот же
backend.

Если вам нужен полностью self-contained стек без внешних зависимостей —
добавьте в `server/docker-compose.yml` сервисы `mimir`/`loki` (не входят в
этот шаблон по умолчанию, чтобы не усложнять базовую версию) и укажите их
адреса в `.env` вместо внешних URL.

## Порядок развёртывания

1. Разверните `server/` — центральный Grafana + Alloy.
2. На каждом мониторимом хосте разверните `agent/`, указав в `.env` адрес
   центрального Alloy (`CENTRAL_REMOTE_WRITE_URL`, `CENTRAL_LOKI_PUSH_URL`).
3. Откройте Grafana и убедитесь, что датасорсы `Metrics`/`Logs` доступны и
   агенты отдают данные (Alloy UI на `:12345/graph` показывает граф
   компонентов и их статус).

Подробности — в README каждой поддиректории.
